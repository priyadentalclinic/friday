PART 3: BAD THINGS / LOOPHOLES IN THE ORIGINAL PLAN
================================================================================

❌ 1. AZURE TTS IS NOT NEEDED
   Your app ALREADY has EdgeTtsManager.kt with Neerja and Swara voices
   via Edge TTS — which is FREE and works. Azure TTS needs a paid
   subscription key. DON'T ADD Azure TTS. Edge TTS already does this.

❌ 2. GOOGLE MAPS API = CREDIT CARD NEEDED
   Directions API requires a Google Cloud billing account.
   Monthly free $200 credit, but can easily exceed.
   Alternative: Use OpenStreetMap or just estimate based on speed+distance.
   The plan treats this as "ask the user" — need a concrete fallback.

❌ 3. NotificationListenerService IS RESTRICTED ON NEW ANDROID
   On Android 14-16 (2026), reading notifications is very locked down.
   User must manually go to Settings → Notification Access → enable.
   Some brands (Xiaomi, Oppo) kill NotificationListenerServices aggressively.
   WhatsApp notifications can be encrypted — body may show as
   "Message" instead of actual text.
   The plan does not mention these restrictions.

❌ 4. CALL_PHONE PERMISSION IS SPECIAL
   ACTION_CALL (direct call dialing) needs CALL_PHONE permission.
   On Android 14+, this is in a special "restricted" category.
   User must manually enable it. If not granted, calling crashes.
   Plan doesn't mention handling permission denial gracefully.

❌ 5. BACKGROUND LOCATION IS ALMOST BLOCKED
   Android 10+ requires ACCESS_BACKGROUND_LOCATION.
   Google Play rejects apps using it unless they have VERY good reason.
   The plan says "track speed" — this needs location in background.
   Also kills battery. Plan doesn't mention battery optimization.

❌ 6. EVERY NOTIFICATION = ONE LLM API CALL = MONEY
   If you get 50 WhatsApp messages in a day, FRIDAY calls OpenRouter
   50 times. For Mom messages it's useful. For group spam it's wasted
   money. Plan doesn't mention filtering or rate limiting.

❌ 7. PLAN IS TOO HIGH-LEVEL
   Doesn't explain:
   - How FRIDAY decides WHICH messages to tell you about
   - What happens if no internet (no TTS, no AI)
   - How to avoid replying to wrong person
   - How to handle message sending errors
   - Battery impact of constant background service

❌ 8. GEMINI/KIMI CHECK — THE PLAN COULD BREAK
   The plan introduces complex service coordination.
   If even one permission is wrong, the whole chain breaks.
   Error handling is not discussed anywhere in the plan.

PHASE 2: ACTION ENGINE (Week 1-2)
───────────────────────────────────
[ ] 2a. Create ActionExecutor.kt
       → Can open apps by package name
       → Can open WhatsApp chat for specific contact
       → Can place calls (ACTION_DIAL, not ACTION_CALL for safety)
       → Uses intents + package manager
[ ] 2b. LLM now returns JSON actions
       → FRIDAY says "Open YouTube" → LLM returns {"action":"OPEN_APP","app":"youtube"}
       → FRIDAY says "Call Mom" → {"action":"DIAL","contact":"Mom","number":"..."}
       → FRIDAY says "WhatsApp Sister" → {"action":"WHATSAPP","contact":"Sister"}
[ ] 2c. Handle permission failures
       → If CALL_PHONE denied → use ACTION_DIAL instead (opens dialer)
       → Tell user what happened: "Boss, I can't directly call without permission"

PHASE 3: NOTIFICATION INTERCEPTOR (Week 2-3)
───────────────────────────────────────────────
[ ] 3a. Create FridayNotificationService.kt
       → Extends NotificationListenerService
       → Listens only for WhatsApp + SMS (ignore other apps)
       → Extracts sender name + message
[ ] 3b. Smart filtering system
       → Ignore group messages / OTPs / spam
       → Only notify about PERSONAL messages from contacts
       → Don't interrupt if user is sleeping (time-based)
[ ] 3c. Privacy-first design
       → Messages processed locally first
       → User must confirm before anything is sent to LLM/AI

PHASE 4: CONTEXT ENGINE (Week 3-4)
──────────────────────────────────────
[ ] 4a. Create ContextEngine.kt
       → Works WITHOUT Google Maps API
       → Uses Android LocationManager for basic speed/distance
       → Estimates time based on: distance from known locations
         (home, work saved in shared preferences)
       → No Google billing needed
[ ] 4b. Driving detection
       → If speed > 25 km/h → "Driving" mode
       → Don't nag while driving. Only interrupt for IMPORTANT messages
       → Read incoming message via TTS when driving (auto)
[ ] 4c. Activity tracking (simple version)
       → If connected to home WiFi → "At Home"
       → If connected to work WiFi → "At Work"
       → If neither → "Out"

PHASE 5: PROACTIVE FRIDAY (Week 4-5) ⭐ THE MOVIE MAGIC
─────────────────────────────────────────────────────────
[ ] 5a. Message → Context → Action pipeline:
       WhatsApp message arrives:
       ↓
       NotificationIntercepter captures:
         Sender: "Mom" | Body: "When will you come home?"
       ↓
       ContextEngine provides:
         Status: "Driving" | ETA Home: "~29 mins"
       ↓
       LLM asked: "Mom messaged 'When will you come home?'
         User is driving. ETA 29 mins. Should we reply?
         Generate short Hindi/English response."
       ↓
       FRIDAY speaks: "Boss, Mom is asking when you'll be home.
         Your ETA is 29 minutes. Shall I reply 'Stuck in traffic,
         will be 29 minutes'?"
       ↓
       User says: "Yes" or "No"
       ↓
       If YES → ActionExecutor sends WhatsApp reply
       If NO → FRIDAY says "Okay, I did not reply"

[ ] 5b. Safety checks before ANY auto-action:
       → Never reply without user confirmation
       → Show preview of message before sending
       → "Boss, shall I say YES or do you want to say something else?"
       → User can cancel at any step

PHASE 6: POLISH (Week 5-6)
───────────────────────────
[ ] 6a. Battery optimization

       → Release WakeLock when idle
       → Batch LLM calls (don't call AI for every notification)
[ ] 6b. Offline fallback
       → No internet → Use native Android TTS (basic)
       → No internet → No AI reply but can still do basic actions
       → Say: "Boss, I'm offline. Can still open apps for you."
[ ] 6c. Voice training
       → Better Hinglish detection
       → Handle mixed sentences: "Mujhe batao weather kya hai"
       → Handle common commands: "Call Mom", "Message Sister",
         "Open YouTube", "Nav bata"
